# Люки САО — журнал самоконтроля

Веб-приложение (PWA, в первую очередь для телефона), в котором районы САО
фиксируют неудовлетворительные люки (ОЛХ) и их устранение, а префектура
принимает исправления. Адрес: https://luki.obhod-sao.ru.

## Как это работает

1. Сотрудник района видит люк в плохом состоянии и нажимает
   «Зафиксировать нарушение»: фото ДО и обязательно — где найден люк: ДТ
   (дворовая территория) или ОДХ (объект дорожного хозяйства) и конкретный
   объект из реестра АСУ ОДС (поиск по названию или подсказка «Рядом с
   вами» по геолокации). По желанию — уточнение места и комментарий.
   Появляется карточка «ОЛХ-001», «ОЛХ-002»… со статусом «Выявлено».
2. После устранения кто-то из того же района открывает ту же карточку и
   добавляет фото ПОСЛЕ — карточка уходит «На проверку».
3. Администратор префектуры в разделе «Проверка» видит ДО и ПОСЛЕ рядом и
   нажимает «Принять» или «Вернуть на доработку» (с обязательным
   комментарием). Возвращённая карточка получает новое фото ПОСЛЕ — в той же
   карточке, вся история фото и решений сохраняется, «Выявлено» от
   повторного исправления не растёт.

«Свод» у префектуры — таблица по 16 районам: выявлено, исправлено (только
принятые префектурой), на проверке, процент исправления; из строки района
открывается подробный свод этого района. Сотрудник района видит только
подробный свод своего района: выявлено, исправлено, на проверке, не
исправлено, процент исправления, возвраты на доработку, среднее время до
приёмки, динамику по дням (период до 31 дня) или месяцам и список «Дольше
всех ждут исправления» (до 10 неисправленных карточек района, без учёта
периода). Везде фильтр по периоду, «Где найдены: Все / ДТ / ОДХ» и
выгрузка в Excel.

### Справочник ДТ и ОДХ

`backend/data/territories.json.gz` — ДТ и ОДХ САО из реестра
reestr-ogh.mos.ru (выгрузка 01.10.2026: 2131 ДТ, 689 ОДХ) с упрощёнными
контурами. API загружает его в базу при старте, если файл поменялся
(`app/load_territories.py`); объекты, пропавшие из новой выгрузки,
выключаются, а не удаляются — на них ссылаются карточки. Новая выгрузка:

```bash
cd backend
python tools/build_territories.py <архив выгрузки .zip или каталог> --date ГГГГ-ММ-ДД
```
— нужны `dt_sao_wgs84.geojson` и `odh_sao_wgs84.geojson` из архива; затем
коммит и обычное обновление сервера.

## Роли и вход

Своих паролей нет: вход логином и паролем журнала обходов
(https://obhod-sao.ru). Приложение проверяет их через API журнала обходов и
выдаёт собственный токен на 8 часов; районы и ФИО берутся оттуда же.
Если вход истёк посреди работы, поверх экрана открывается окно «Войдите
снова» (нужен только пароль): выбранные фото и заполненная форма остаются, а
прерванная отправка фото и карточки продолжается сама после входа. За 15
минут до конца входа то же окно появляется заранее — при открытии формы
нарушения и перед добавлением фото в карточку.

| Роль в журнале обходов | Здесь | Что может |
|---|---|---|
| инспектор, проверяющий района | сотрудник района | заводит карточки и добавляет фото ПОСЛЕ в своём районе; журнал и свод — только своего района |
| инспектор или проверяющий без района | «Район не назначен» | ни журнала, ни свода — откроются, когда администратор журнала обходов назначит район |
| администратор | Префектура | всё видит (журнал и свод по всем районам), принимает и возвращает карточки, может завести карточку в любом районе |

Свод по всем районам и журнал всего округа видит только префектура; районы —
только свой район.

## Стек

- backend: FastAPI, SQLAlchemy 2 (async, asyncpg), Alembic, PostgreSQL 16,
  Pillow + pillow-heif (превью фото, в т.ч. HEIC с iPhone), openpyxl (Excel);
- frontend: React, TypeScript, Vite, Tailwind CSS v4, TanStack Query, PWA
  (vite-plugin-pwa);
- прод: docker compose рядом с журналом обходов, см. `deploy/README.md`.

## Локальный запуск

Целиком в Docker (приложение — http://localhost:8080, API —
http://localhost:8000/api/docs):
```bash
docker compose up --build
```
Вход идёт через настоящий журнал обходов — по умолчанию https://obhod-sao.ru
(`JIRAJURA_API_URL` в `docker-compose.yml`).

Без Docker:
```bash
# backend (нужен PostgreSQL на localhost:5432)
cd backend
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements-dev.txt
export DATABASE_URL=postgresql+asyncpg://postgres:postgres@localhost:5432/luki_sao
export JIRAJURA_API_URL=https://obhod-sao.ru
alembic upgrade head
uvicorn app.main:app --reload --port 8010

# frontend
cd frontend
npm ci
LUKI_API_PROXY=http://localhost:8010 npm run dev   # http://localhost:5173
```

## Тесты

```bash
cd backend && python -m pytest -q
cd frontend && npm run lint && npm run build && npm test
```
Backend-тесты создают и удаляют свою БД (`TEST_DATABASE_URL`, по умолчанию
`postgresql+asyncpg://postgres:postgres@localhost:5432/luki_sao_test`) и
подменяют журнал обходов — сеть не нужна. Всё это же гоняет CI
(`.github/workflows/ci.yml`) на каждый PR.
