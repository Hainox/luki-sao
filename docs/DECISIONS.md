## 2026-10-01 — Истёкший вход: окно повторного входа, а не продление токена
**Кто:** владелец продукта (направление), Claude Code (реализация)
**Контекст:** на любой 401 клиент уводил на `/login` полной перезагрузкой —
фото ДО/ПОСЛЕ, уже выбранные, но не отправленные, и заполненная форма
пропадали. Сотрудник района снимает в поле, токен живёт 8 часов — вход
может закончиться посреди съёмки или отправки.
**Решение:** на 401 страница остаётся на месте, поверх неё — окно «Время
входа истекло» (логин подставлен и не меняется, нужен только пароль).
Отправка фото и создание карточки на 401 не считаются сбоем: они ждут входа
и повторяются сами (создание — с тем же id карточки). «Выйти» в окне — обычный
выход, черновик сбрасывается. Если до конца входа меньше 15 минут, то же
окно открывается заранее (с кнопкой «Позже») при открытии формы нарушения
и перед съёмкой фото; срок сверяется с часами сервера (заголовок `Date`),
а не телефона. Сервер не менялся.
**Обоснование:** срок жизни токена владелец ещё не выбрал, а «тихое»
продление токена при каждом запросе держало бы в приложении и тех, кого в
журнале обходов уже отключили, — пароль проверяет только журнал обходов,
при входе. Повторный ввод пароля раз в смену — приемлемая цена.

## 2026-09-30 — Отдельное приложение, а не раздел журнала обходов
**Кто:** владелец продукта (решение), Claude Code (реализация)
**Контекст:** в журнале обходов (JiraJura) в тот же день вышел осмотр люков
внутри обхода площадки. Руководство уточнило задачу: нужен самоконтроль люков
по всей территории САО — карточка выявленного люка с фото ДО, фото ПОСЛЕ в той
же карточке, приёмка префектурой и свод по районам. Перечня люков нет —
люк появляется, когда его выявили.
**Решение:** отдельное приложение со своей БД и своим поддоменом
`luki.obhod-sao.ru`; площадочный журнал люков из JiraJura удалён.
**Обоснование:** модель другая (карточка без обхода, площадки и перечня;
статусы и свод свои) — встраивание дублировало бы цикл устранения
замечаний JiraJura под другие правила. Два журнала люков одновременно путали
бы районы.

## 2026-09-30 — Вход логином журнала обходов, свой токен
**Решение:** своих паролей нет. `POST /api/auth/login` проверяет логин и
пароль через `POST /api/v1/auth/login` JiraJura по внутренней docker-сети
(`http://api:8000`), передавая настоящий адрес клиента в `X-Real-IP`, и
выдаёт собственный JWT (8 ч). Токен JiraJura не хранится. При каждом входе
обновляются снимок пользователя (id = id в JiraJura, роль, район) и список
районов (UUID районов JiraJura — первичные ключи и здесь).
**Обоснование:** сотрудники уже знают этот логин, администрировать вторую
базу пользователей некому. `X-Real-IP` обязателен: JiraJura ограничивает
попытки входа по нему, без заголовка все сотрудники выглядели бы для неё
одним адресом (адресом контейнера) и блокировали бы друг друга. Доверять
заголовку можно, потому что до `luki-api` доходят только контейнеры
docker-сетей, а портов наружу нет.

## 2026-09-30 — Карточка — одна на выявленный люк, исправления — попытки внутри
**Решение:** у карточки одна серия фото ДО (`attempt = 0`) и попытки ПОСЛЕ
(`attempt = 1, 2, …`). Первое фото ПОСЛЕ попытки переводит карточку «На
проверку»; возврат префектурой (с обязательным комментарием) открывает
следующую попытку. «Выявлено» в своде — число карточек, созданных в периоде,
поэтому повторное исправление его не увеличивает.
«Исправлено» — только принятые префектурой; процент = исправлено /
выявлено × 100, «—» при нуле выявленных; период — по дате создания карточки,
московское время.
**Обоснование:** так утвердил владелец продукта по макетам «Фотожурнал» и
«Свод по люкам»; история фото и решений не теряется, а свод нельзя
«накрутить» повторными отправками.

## 2026-09-30 — Размещение рядом с журналом обходов через его proxy
**Решение:** отдельный compose-проект без опубликованных портов; `luki-web`
и `luki-api` входят во внешнюю сеть `jirajura_default` под этими именами,
поддомен отдаёт proxy JiraJura своим server-блоком (включается там
`deploy/scripts/enable-luki-sao.sh` после выпуска сертификата).
**Обоснование:** порты 80/443 на сервере уже заняты proxy JiraJura. Имена
`luki-*` у всех сервисов, включая БД, — имя сервиса становится DNS-именем во
всех его сетях: второй `api` в `jirajura_default` перехватывал бы запросы к
JiraJura, а `luki-api` по имени `db` попадал в БД JiraJura (первый запуск
01.10.2026 упал именно на этом).
